4 Acquiring maps

Every analysis starts with a study area and a maps object. There are four routes to it: selective download of MapBiomas tiles, the national collection stored on your computer, selective reading over HTTP, and a local folder with maps of any collection. All of them lead to the same object, used by every other function in the package.

Study area

The area is a polygon in any coordinate reference system, stored as a GeoPackage (.gpkg), shapefile (.shp, with its .prj) or GeoJSON, or already loaded as an sf object. The path can be given with or without extension, or be the folder holding a single area file; with .gpkg and .shp of the same name, the .gpkg is used. The package already includes the boundary of the UFSCar Lagoa do Sino campus, used in this chapter:

ufscar <- system.file("shp", "UFSCar.shp", package = "biomastats")

A shapefile is a set of files. Without its .prj, it loses its coordinate reference system and loading stops with a message. When copying or sending an area, include every file of the same name, or prefer a GeoPackage, which is a single file.

When no area is at hand, make_polygon() draws the area from a centre point, a shape ("circle", "square" or "hexagon") and the total width in km (size), which is the circle’s diameter, the square’s side or the distance between opposite vertices of the hexagon. A hexagon of about 12.5 km² centred on the campus, like the example area in Part II, looks like this:

area <- make_polygon(lat = -23.605, lon = -48.529, size = 4.4,
                     shape = "hexagon")

make_polygon() writes the result as polygon.shp in the shp folder of the installed package, replacing the previous file. To keep an area, save the returned object (area$polygon) with sf::st_write() in a folder of your own.

MapBiomas splits Brazil into tiles, and compare_shapefiles() tells you which ones cover the area. Lagoa do Sino fits entirely within tile 93:

unique(compare_shapefiles(ufscar))
[1] 93

Figure 4.1: Tile grid used for selective acquisition. Highlighted: tile 93, which contains Lagoa do Sino (dot).

Route 1: selective download

Here the package downloads from the Bioma Stats API only the tiles and years the area needs. If the area crosses more than one tile, the neighbouring tiles are merged before the final crop and the mask by the boundary. The files are kept in the folder you choose and reused in later runs.

maps <- load_rasters(ufscar, start = 1985, end = 2024, method = "download",
                     export_folder_path = "mapbiomas-tiles")

Route 2: local national collection

Here the national map for each year is downloaded only once. After that, any area can be cropped from it without an internet connection, which makes this route the better choice for many areas or for large ones.

download_mapbiomas(dest_dir = "collection_10", data_type = "cover",
                   collection = 10, time_range = c(1985, 2024))

maps <- load_rasters(ufscar, start = 1985, end = 2024, method = "library",
                     import_folder_path = "collection_10")

Both routes produce the same object: for the Lagoa do Sino example area, the 40 maps cropped from the national collection are identical, cell by cell, to those obtained by selective download.

Route 3: selective reading over HTTP

MapBiomas annual maps are in a public repository, as GeoTIFFs split into blocks. With method = "http", load_rasters() reads only the blocks that cover the area, without login and without downloading the whole national file. The product is chosen by its id. With export_folder_path, the windows read are saved as product_year.tif, together with the area (area.gpkg):

maps_http <- load_rasters(ufscar, start = 2023, end = 2024, method = "http",
                          product = "mapbiomas_brasil_c10",
                          export_folder_path = "maps-lagoa")

Any other annual GeoTIFF split into blocks can be read too, with url and {year} in place of the year. Brazilian collections use the MapBiomas legend; those of other countries have their own legends, which come in through the dictionary (next section).

Route 4: local folder, any collection

Maps from other sources (windows saved by route 3, MapBiomas at 10 m, state maps, your own classifications) come in through a folder with one GeoTIFF per year, named prefix_year.tif. load_local_rasters():

  1. checks each file: one layer, coordinate reference system, integer codes and coverage of the area;
  2. harmonizes every year to the grid of the first with nearest neighbour, which does not mix class codes;
  3. crops and masks by the area and handles no-data pixels (nodata, 0 by default).

The area can be in the folder itself. Maps that cover only part of the area, such as windows saved for another region, are refused:

maps_again <- load_local_rasters(folder = "maps-lagoa", collection = 10)

When the collection uses the MapBiomas legend, collection = 10 brings names and colours. For another legend, class_dictionary() builds a template with the codes present and then reads the completed dictionary (code, name and colour, in Portuguese or English):

template <- class_dictionary(maps_again)
write.csv(template, "legend.csv", row.names = FALSE)
dictionary <- class_dictionary(maps_again, file = "legend.csv")
maps_again <- load_local_rasters(folder = "maps-lagoa", dictionary = dictionary)

Extended context

Connectivity indices suffer from edge effects: the area boundary cuts fragments and hides stepping stones outside it. context_m widens the reading with a band around the area, in metres. The object keeps the original area as focal, used by the connectivity analyses (chapter 13):

maps_context <- load_rasters(ufscar, start = 2024, end = 2024, method = "http",
                             product = "mapbiomas_brasil_c10", context_m = 2000)

The maps object

All four routes return a list with the area boundary (shape), the period (time_range), one map per year (raster) and the collection (collection). It also keeps the origin of the maps (source), which allows a larger area to be reloaded through the same route; the class dictionary (class_dictionary), for local collections; the original area (focal), with a context; and reading details (metadata). The object can be saved and shared, so the acquisition does not need to be repeated:

save(maps, file = "lagoa-do-sino.Rdata")
load("lagoa-do-sino.Rdata")

The package already includes the maps object for the Lagoa do Sino example area, from 1985 to 2024, which is used throughout Part II.
